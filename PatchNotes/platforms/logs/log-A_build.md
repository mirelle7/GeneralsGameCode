## Notes for builders
- **Orphaned files from theirs, left in place because they are outside my group**: `cmake/patch_bink_static.cmake` and `cmake/patch_miles_static.cmake` (nothing references them now). Also `Core/Libraries/Source/debug/debug_stub_nonwindows.cpp` and `Core/Libraries/Source/profile/profile_stub_nonwindows.cpp`, which no CMake file references. `GGC_USE_WINMAIN` in `cmake/sdl3.cmake` is now unused.
- **Will break**: `Dependencies/Utility/Utility/STLUtils.h` (not my group) does `#include <Utility/CppMacros.h>`, but that header no longer exists. Trunk moved it to `Dependencies/Precompiled/Precompiled/CppMacros.h`, which BasePrecomp force-includes. Drop the include or change it to `<Precompiled/CppMacros.h>`.
- **SDL_main vs `/ENTRY`**: theirs' `SDL3Main.cpp` includes `<SDL3/SDL_main.h>`, which renames `main` to `SDL_main` and provides WinMain. Trunk links desktop Windows SDL3 builds with `/ENTRY:mainCRTStartup` and a plain `main()`. Whoever merges `SDL3Main.cpp` must keep `SDL_main.h` away from desktop Windows (UWP and Android need it). Otherwise the desktop win32/win64 SDL3 link fails with no `main`.
- **render2dsentence.cpp** (another group) needs `<stb/stb_truetype.h>` from `GGC_BGFX_STB_INCLUDE_DIR` on non-Windows and UWP. That path is propagated from bgfx.cmake into the WW3D2 interface. The wasm build embeds `/fonts/DejaVuSans*.ttf` (HEAD), not theirs' `/fonts/droidsans.ttf`.
- **Cross builds now build a host shaderc automatically**. `GGC_BGFX_HOST_SHADERC` covers Android, iOS, Switch and UWP; the build uses an ExternalProject with the host's default compiler. For UWP, Android and Switch, run configure from a shell where a host C++ compiler is found, or pass `-DGGC_SHADERC_EXE=...`.
- **Presets** now include HEAD's set plus theirs' `win64-bgfx-standalone[-debug]`, `android-`, `switch-` and `web-generalsmd-sdl3-bgfx` (HEAD's web version is kept). The `win32-bgfx-standalone*` presets are gone: trunk removed them along with the `GGC_BGFX_STANDALONE` flag, and `win32-bgfx` replaces them. Theirs never had iOS or UWP/Xbox presets; those are configured by hand. Theirs' presets still set `GGC_BGFX_STANDALONE=ON`, which only makes the root CMakeLists include `dx8.cmake`. That is harmless.
- FFmpeg: Android and iOS self-compile it through `cmake/ffmpeg.cmake` (needs bash, make and the cross toolchain). Switch and desktop use `find_package(FFMPEG)`.
