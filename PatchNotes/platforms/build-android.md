# build-android (pf/android, Zero Hour, arm64-v8a, modern mode RETAIL_COMPATIBLE_GAME=OFF)

Configure OK, build OK (libz_generals.so 102 MB), APK built, installed and run on Android phone (<device-serial>, Android 15, Adreno):
intro movie (FFmpeg) -> loading screen -> main menu with the 3D shell map running (Vulkan/GLES bgfx), game loop ticking ~30 fps, no crash.
Not done: Generals (Zero Hour only), -mathCrcCheck / SimulationMathCrc values in either mode (no command-line injection set up), Retail-compatible mode, gameplay beyond menu, audio check, orientation (shows portrait).

## Commands (PowerShell, VS 2026 BuildTools dev shell x64 for host shaderc; PATH needs Git usr\bin, Git mingw64\bin (xz for FFmpeg tarball), NDK prebuilt make, VS cmake+ninja)
    $env:ANDROID_NDK_HOME = "C:/Users/<you>/AppData/Local/Android/Sdk/ndk/25.1.8937393"   # forward slashes, backslashes break CMakeSystem.cmake
    cmake --preset android-generalsmd-sdl3-bgfx -DCMAKE_MAKE_PROGRAM=<VS ninja> -DRTS_BUILD_OPTION_RETAIL_COMPATIBLE_GAME=OFF
    cmake --build build/android-generalsmd-sdl3-bgfx --config Release --target z_generals -- -j8
    ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk bash scripts/android/build-apk.sh build/android-generalsmd-sdl3-bgfx build/android-generalsmd-sdl3-bgfx/ggc.apk
    adb -s <device-serial> install -r ggc.apk ; appops set com.generals.launcher MANAGE_EXTERNAL_STORAGE allow ; am start -n com.generals.launcher/.GameActivity
Game data was already in /sdcard/Games/Generals. The installed app was the old Box64 build (same package); it was replaced.
The old Gradle project was never committed, so scripts/android/build-apk.sh (aapt2/javac/d8/zipalign/apksigner, SDL Java from the SDL tarball, GameActivity loads openal, SDL3, z_generals) is new.
